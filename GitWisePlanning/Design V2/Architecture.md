Frontend ^egdaa3o0

Establish a reply queue that the UI or caller listens on. The background task can send messages to the queue that indicate status and completion. Data that the background task must return to the caller can be placed into the messages. If you are using Azure Service Bus, you can use the ReplyTo and CorrelationId properties to implement this capability. ^oXS49nVM

1. Frontend sends a request to the UI service that has a developer, day and a tenant, wants to get a summary of their work. ^OzYeL10X

Control Plane DB ^JuDaXR7y

1. The FE sends a request to the control plane asking it for a work summary.
This request includes:
* tenantId
* developerId
* summaryDate

2. The Control Plane handles the request and checks its database for a job with that
same tenant, developer and date.

3. If no job exists, create a new row and set it to status pending.
4. The Control Plane publishes a message to the queue for the Summary engine to pick up.  This message contains the jobId, tenantId, developerId and summaryDate.

5. Summary Engine consumes the job, it checks for an existing summary with the same date, tenant and dev combination, if it exists then checks the freshness
6. Summary Engine then pushes an event to the Control plane with the job Id and the summary Id

7. the Control Plane updates the processing job to complete and its existingSummaryId.

8. The FE on its next poll of the jobId sees it is complete and then retrieves the summary by the Id, the control plane retrieves this from the summary engine.
     ^5y60GuhA
